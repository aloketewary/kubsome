# Request-scoped API security and runtime hardening

This change adds WebSocket token checks, request-scoped context headers, stricter terminal command parsing, subprocess timeouts, non-root container settings, and version/CI updates. WebSocket routes authenticate before accept, direct kubectl access is narrowed, and Helm defaults to read-only RBAC. The request-context implementation is not isolated from existing caches and thread pools, so users can receive data from another context; the terminal allowlist also still admits mutating kubectl subcommands. **Watch for:** **confirmed** cross-context cache/executor leakage, **confirmed** terminal policy bypasses, **confirmed** Docker API version fallback to `0.0.0`, and **confirmed** WebSocket handshakes bypassing the HTTP rate limiter.

**Verdict**: NEEDS_CHANGES

## High-level view

**Confirmed:** `ContextMiddleware` gives each request a cloned `ContextVar`, but context-dependent no-argument collectors retain process-global cache keys. That makes the new isolation boundary ineffective for cached pods, events, deployments, uptime, and similar data. **Confirmed:** `run_in_executor` and `ThreadPoolExecutor` calls do not inherit the request context, so WebSocket streams and parallel diagnosis queries can fall back to the default cluster.

**Confirmed:** WebSocket authentication runs before `accept()` and supports the browser query-token flow, but the token is placed in the URL and the handshake is outside `RateLimitMiddleware`. **Confirmed:** the terminal parser blocks obvious shell-prefix collisions while still allowing `kubectl config` and other mutation-capable subcommands.

**Confirmed:** selected API subprocesses now have deadlines, but pod-name completion remains unbounded and context switching lets `TimeoutExpired` escape to the CLI. **Confirmed:** the Docker image copies `pyproject.toml` without installing the project, so the new metadata-backed API version reports `0.0.0`; the pinned kubectl download also has no integrity verification.

<summary>Issues (10)</summary>

1. **Contextless collector cache keys** — **confirmed:** no-argument cached collectors use only the function name as their key while reading request-scoped context, allowing one cluster's data to be served to another. Include context and namespace in cache keys or pass them explicitly.
2. **Executor context loss** — **confirmed:** WebSocket and diagnostic worker threads do not receive the active `ContextVar`, so their kubectl calls use process defaults. Use `asyncio.to_thread`/copied contexts or pass context and namespace as explicit arguments.
3. **API switch still mutates shared kubeconfig** — **confirmed:** `persist=False` skips state-file persistence but still runs `kubectl config use-context`, changing the shared kubeconfig for other requests and CLI processes. Avoid changing kubeconfig for request-scoped switches.
4. **Terminal policy bypasses** — **confirmed:** allowing top-level `config` and `auth` admits mutating kubectl subcommands, and `--context=...`/`--namespace=...` are not normalized by the scope-injection checks. Allow only individually read-only subcommands and enforce normalized scope flags.
5. **WebSocket token exposure** — **confirmed:** browser authentication sends the bearer token as `?token=...`, making it available to URL access logs, proxy logs, and browser history. Prefer a short-lived handshake token or a subprotocol/cookie design with appropriate CSRF protection.
6. **WebSocket rate-limit bypass** — **confirmed:** `RateLimitMiddleware` handles HTTP `Request` paths only, while every WebSocket handshake bypasses it. Add handshake throttling and connection limits at middleware or the edge; use a shared limiter when running multiple workers or replicas.
7. **Incomplete timeout handling** — **confirmed:** `get_pod_names()` still calls kubectl without a timeout, and `switch_context()` does not catch its new `TimeoutExpired`, so completion can hang and CLI switching can terminate with an uncaught exception. Add bounded handling to both paths.
8. **Container version metadata drift** — **confirmed:** the Dockerfile never installs the local project, so `importlib.metadata.version("kubsome")` fails and `core.version` falls back to `0.0.0` despite the image and Helm tag being `1.13.33`. Install the package or provide a build-time version source.
9. **Unverified kubectl supply chain** — **likely:** the Dockerfile downloads an executable over HTTPS based only on a version argument and never checks a published checksum or signature. Verify the artifact before placing it in `/usr/local/bin`.
10. **Missing boundary tests** — **confirmed:** the suite does not exercise concurrent context headers, context-sensitive cache isolation, executor propagation, WebSocket rate limits, terminal mutation/flag forms, timeout expiry, or Docker-installed metadata. Add focused tests for those boundaries.

<summary>Details</summary>

### Request context isolation stops at caches

`core/context.py:48-79` introduces a cloned `ContextVar` scope, but `core/cache.py:28-35` derives keys from function arguments only. Context-sensitive collectors such as `core/collectors/pods.py:6-11` are cached with no arguments, producing one `collect_pods` entry for every context and namespace. **Confirmed:** request A can populate that entry from cluster A, then request B receives it while its response labels cluster B. The same shape exists in other no-argument cached collectors. Cache keys need an explicit `(context, namespace)` dimension, or collectors need to accept those values as arguments.

**Confirmed:** the isolation does not cross executor boundaries. `api/routes/ws.py:61-79` calls `collect_pods` and `collect_events` through `run_in_executor`, which does not propagate `ContextVar` state; those collectors read `_default_context` in the worker. `core/collectors/diagnosis.py:24-29` has the same issue with `ThreadPoolExecutor` around `pod_events` and `pod_logs`. Context-selected streams and diagnostics therefore query the process default rather than the request-selected cluster. Pass the scope explicitly or run the worker with a copied context.

### Request-scoped switch still has a process-wide side effect

`api/routes/contexts.py:46` calls `switch_context(target, persist=False)`, but `core/context_switcher.py:11-23` always executes `kubectl config use-context` before deciding whether to call `save_state`. **Confirmed:** concurrent API clients still race through the shared kubeconfig and can change the active context seen by other subprocesses and CLI processes. Request-local selection should only update the scoped object and pass `--context` to commands; it should not modify kubeconfig.

### Terminal restriction leaves mutation-capable kubectl paths

The token check at `api/routes/terminal.py:64-81` treats `config` and `auth` as read-only roots. **Confirmed:** `kubectl config set-context`, `kubectl config use-context`, `kubectl config delete-context`, and `kubectl auth reconcile` pass this check even though they mutate local or cluster state. The comment promising read-oriented passthrough is false. Replace the root set with explicit safe subcommands, especially `config view` and non-mutating auth queries.

The same function only checks exact flag tokens when adding defaults at `api/routes/terminal.py:118-132`; forms such as `--context=other` and `--namespace=other` are not recognized by those checks. **Likely:** if the endpoint is intended to enforce the request-selected cluster and namespace, these forms let callers override the injected scope. Normalize `--context`/`--namespace` in both `--flag value` and `--flag=value` forms, then enforce the intended policy.

### WebSocket authentication and throttling boundaries

`api/auth.py:45-69` validates before accepting each WebSocket. **Confirmed:** the browser implementation in `ui/src/app/core/services/ws.service.ts` places the bearer token in the query string. URL-bearing credentials can enter reverse-proxy access logs, tracing metadata, browser history, and referrer-related tooling. Use a short-lived WebSocket ticket or negotiate a safer credential channel; if cookies are used, enforce origin/CSRF policy.

`api/ratelimit.py:45-53` only processes HTTP requests under `/api`; the WebSocket routes in `api/routes/ws.py:21-164` are not covered. **Confirmed:** an attacker can open unlimited authentication handshakes and authenticated long-lived streams without consuming an HTTP bucket. Add per-IP handshake limits and a maximum connection/stream budget. **Confirmed:** the limiter is also process-local (`api/ratelimit.py:1-10`), so deployments with multiple workers or replicas multiply the allowance unless an ingress or shared store is configured; Helm permits `replicaCount` greater than one without provisioning such a limiter.

### Deadline coverage is partial and failure handling is inconsistent

The changed API calls add finite deadlines, but `core/k8s.py:87-101` leaves `get_pod_names()` without one even though terminal completions invoke it. **Confirmed:** a stalled kubectl process can occupy a worker indefinitely. Add the same bounded timeout and return an empty completion/error result on expiry.

`core/context_switcher.py:17` adds `timeout=10` without catching `subprocess.TimeoutExpired`. **Confirmed:** CLI context switching now raises instead of reporting a failed switch, while the API path becomes a generic 500 through middleware. Catch the timeout, leave the active context unchanged, and return a controlled failure. The newly timed API subprocesses should likewise translate expiry into their documented empty/error response rather than relying on broad middleware conversion.

### Container packaging and security alignment

`api/app.py:57` now uses `core.version.__version__`, which reads installed distribution metadata and falls back to `0.0.0` at `core/version.py:15-17`. **Confirmed:** `Dockerfile:34-45` copies `pyproject.toml` but does not run `pip install .`; only `requirements.txt` dependencies are installed. The container's `/api/version`, OpenAPI version, and startup metadata therefore diverge from `1.13.33`. Install the built project or inject the version during the image build.

`Dockerfile:14-22` pins a kubectl version and architecture but accepts the downloaded bytes without checksum/signature validation. **Likely:** a compromised mirror, proxy, or future build-argument override can place an altered executable in the runtime image. Verify the official release digest before chmod/install.

### Test coverage

`312` tests pass and Python compilation succeeds. **Confirmed:** coverage does not exercise concurrent requests with different context headers, cached collector isolation, executor propagation, WebSocket rate limits, `kubectl config`/`--flag=value` terminal cases, timeout expiry behavior, or the Docker-installed metadata path. Add focused tests for those boundaries before shipping.
